# Antislop standard

Use this as a quality filter for every skill in this pack. Match the check to the task; do not turn it into extra ceremony.

## Core rule

Produce work that is specific to the user's request and supported by the project or reliable evidence. Remove generic filler, repeated advice, unsupported claims, fabricated examples, and complexity that does not solve the requested problem. Prefer concrete nouns, direct verbs, and the smallest clear implementation.

## Apply by artifact

- **Code:** preserve existing conventions; make the smallest coherent change; avoid speculative abstractions and comments that restate code. Add comments only for non-obvious intent or constraints.
- **Plans and specs:** tie each requirement to a user need, observable outcome, or real constraint. Remove template sections that add no decision value.
- **Research and technical claims:** verify unstable or niche facts against primary sources when practical. Separate observed facts from inference and label unknowns.
- **Copy and documentation:** use plain, precise language. Remove empty superlatives, canned transitions, repeated conclusions, and claims without evidence.
- **Interfaces:** follow supplied design direction. Give each visual choice a purpose; avoid generic gradients, glow, decorative badges, uniform card grids, and stock template sections. Keep controls functional, keyboard accessible, responsive, and clear in loading, empty, and error states.
- **Reviews and reports:** report only issues supported by evidence. State what was inspected and what remains unverified.

## Final pass

Before handing work back, ask:

1. Does each part serve the request or a required constraint?
2. Is any claim, example, metric, or behavior invented or unverified?
3. Is there repeated, vague, or default content that can be removed or made specific?
4. Does the result work with the project's conventions and the user's direction?
5. Does the verification summary describe checks that actually ran?

Fix any answer that reveals a real defect. Keep the final response concise and evidence-based. If this reference is unavailable in a single-skill installation, apply the Core rule and the artifact-specific guidance above.
