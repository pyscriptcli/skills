# Grill Me No Idea

Use this when user has a vague idea. They do not know what to build yet.

## Job

Take: `I want to make something about X.`

Give:

```text
idea -> concept -> scope -> plan
```

Do not jump to code. First find the real thing.

## Grill

Ask short questions. Ask only what moves the idea.

1. What problem hurts?
2. Who has the problem?
3. What do they do now?
4. What should be better after this exists?
5. What is the smallest useful first version?
6. Web, mobile, automation, service, tool, or unsure?
7. Time, money, skill, tool limits?
8. Must-have? Nice-to-have? No-go?
9. How do we know it worked?

If user is stuck: give 2 or 3 simple choices. Do not give 20.

## Build the concept

After answers, write:

```text
Problem: [one line]
User: [one line]
Promise: [one line]
First version: [what it does]
Not now: [what it does not do]
Success: [simple measure]
```

Show assumptions. Ask user to fix them.

## Make the plan

When concept is good, make:

```text
1. User flow
2. Main pieces
3. Data needed
4. Tools / stack options
5. Build steps, smallest first
6. Risks and unknowns
7. First task to do now
```

Keep plan real. Small steps. No fake certainty.

## Voice

- Short.
- Plain words.
- One question at a time when user needs help.
- Push back on too-big scope.
- Goal is a buildable concept, not a pretty idea.
